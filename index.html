TL;DR

  • Smarter selection has little room. When a language model's memory of past tokens grows too large, eviction methods keep some tokens and drop the rest. Searching for the best possible set to keep in 220,656 cases from eight models, we find it beats simply keeping the most-attended tokens by a median of only 2 to 5% of the remaining error, and a simple swap rule finds that improvement.
  • A cheap signal shows when it matters. The share of attention that lands on the dropped tokens predicts which cases have room to improve, across ten models.
  • Some benchmark wins come without memory savings. In the standard benchmark library, several leading methods, including KVzip, hide dropped tokens instead of deleting them, so they still use all of the memory. Making them truly delete down to the same size costs 14 to 62 benchmark points, and an 87.6-point retrieval gain comes from letting the method read the question before deciding what to keep.
  • ContourKV. A simple method that uses KVzip's scores but truly deletes tokens. It beats KVzip in 93 of 160 benchmark runs while using 28 to 1078 times less memory, and ties Compactor, the strongest method that also saves memory.

Forced weights

As a language model reads, it stores information about every past token so it can look back at it. This memory grows with the length of the text and becomes the main cost for long inputs. Eviction methods keep it small by deleting most past tokens and keeping a fixed number.

When the model looks back, each token gets an attention weight, and the weights add up to 1. After eviction, the model can only look at the tokens it kept, and it simply scales their original weights up until they add up to 1 again. It cannot change the weights to make up for what was dropped. So the only decision an eviction method makes is which tokens to keep.

That has a useful consequence. The error from dropping tokens equals the share of attention that was dropped, times how far the dropped tokens' average is from the kept tokens' average. When little attention lands on the dropped tokens, no choice can do much better than keeping the most-attended ones. Finding the truly best set is still a hard computational problem, even in the simplest cases.

Selection ceiling

We compared keeping the most-attended tokens against the best possible set of the same size, searched among a shortlist of the most promising tokens, keeping 4 to 32 tokens per attention head. Across 220,656 cases from eight models, the best set removes a median of 2.1 to 4.7% of the remaining error. A simple rule finds it: start from the most-attended tokens and swap one at a time while the error keeps falling. An exact search over all tokens, run on 960 cases from the four main models, keeps the median below 12%.

Beyond 32 tokens a complete search is too expensive, but the swap rule still shows how much is possible at least. That share stays flat as the memory grows, while the attention on dropped tokens, and with it the error itself, keeps shrinking.

Dropped mass

The share of attention that lands on the dropped tokens predicts the cases where a better choice cuts the error by more than 10%. Across ten models, it ranks such a case above one without room 76 to 89% of the time, better than earlier error bounds. Averaged over each attention head, it forms a map, and which heads have room is decided by how the model is built.

Popular methods

Popular methods are far from this limit. Keeping 8 tokens, SnapKV, H2O, Quest and StreamingLLM have 1.4 to 2.0 times the error of the best choice, while keeping the most-attended tokens comes within 3% of it on three of the four main models. When one saved memory has to serve every later question, the gap grows to as much as 4.2 times for TOVA, H2O and SnapKV. Most of that gap comes from guessing wrong about which tokens will matter, so differences between these methods mostly reflect how well they guess.

Measured memory

We tested 14 methods from NVIDIA's kvpress library, plus H2O, on two standard long-text benchmarks, RULER and LongBench, with four models and texts of 4,096 to 32,768 tokens. The library stores each layer's memory as one block in which every attention head gets the same number of slots. Methods that give different heads different amounts, including KVzip, therefore cannot delete anything. They hide the dropped tokens and keep the whole memory.

When the same choices are made to truly delete down to the target size, scores fall in 140 of 157 runs: by 14.1 points on LongBench and by up to 62.2 points on RULER.

Retrieval gains come from seeing the question

In the needle-in-a-haystack test, the test setup drops tokens after the question has already been read, so the method can use the question to decide what to keep. Re-running eight matched cases on Llama-3.1-8B so that the method decides without the question erases the gain, and the extra memory explains none of it.

ContourKV

ContourKV keeps the most recent tokens (up to 32) in every head plus that head's highest-scoring tokens, and deletes the rest, so every head holds exactly the target number. With KVzip's scores, it differs from KVzip only in how many tokens each head gets, in keeping recent tokens instead of the first four, and in deleting tokens instead of hiding them.

With the size enforced, ContourKV beats KVzip in 93 of 160 runs and loses 22, while using 28 to 1078 times less memory. Sixteen of those losses come from one setting, RULER with 32 tokens, where KVzip's full memory beats every method that truly saves memory. Against Compactor, the strongest method that also saves memory, it ties, as expected when both are already close to the best possible choice. KVzip's scores take 8.7 to 13.6 times longer to compute than reading the text once; with SnapKV's cheaper scores, ContourKV ties SnapKV.

Next-word prediction

Everything above measures how much each look-back changes. What matters in the end is how well the model predicts the next word. Using the swap rule only in the heads our map flags improves next-word prediction on five of eight models, capturing 88 to 98% of the improvement from using it everywhere. On the three Qwen3 models the map flags the wrong heads. The swap rule needs the full, uncompressed result, which a real system does not have, and a small predictor trained to imitate it recovers at most 5% of the improvement.

Limitations

  • A lower bound. The exact search finished on only 159 of 939 cases, so the true best choice could be somewhat better than what we report.
  • Look-backs, not answers. We measure how much each attention look-back changes, not the quality of the model's answers.
  • One question at a time. Keeping the most-attended tokens is near-best for the current question. A memory reused for later questions has to choose before seeing them.
  • Model range. Standard-attention models from 0.6B to 14B parameters, and texts up to 16,384 tokens for the analysis.
